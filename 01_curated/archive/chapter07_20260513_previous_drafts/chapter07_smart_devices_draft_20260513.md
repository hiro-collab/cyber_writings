# 第7部　スマートデバイス、魔法、魔人

## 第7章　スマートデバイスは術を通す器として見える

ここまで、デジタル技術を日本語の身体感覚で捉え直してきた。

第3章では、サイバーの技を「どうしたいか」から分類した。入力したい、見たい、見せたい、つなぎたい、きっかけで動かしたい、相互作用させたい、繰り返し呼び出したい。技術名や製品名ではなく、人が何をしたいのかから、操るための技を見た。

第4章では、そのような語りが日本語では陰陽師や術のように聞こえやすいことを確認した。ただし、それはデジタル技術を神秘化するためではなかった。状態を読み、記号を置き、作法に従い、代理的なものに働かせ、現実の変化へつなげるという操作構造を、日本語の中でどう理解するかという問題だった。

第5章では、その操作構造がGUI、プロジェクション、身体入力を通じて、人間の前にどう現れるかを見た。サイバーの操作場は、画面の中だけに閉じていない。壁、床、物体、身体のそばに、状態や選択肢や操作可能性として現れる。

第6章では、その操作場で働くものとしてAIエージェントを扱った。AIエージェントは、人格や魂としてではなく、人の願いを受け取り、文脈を読み、手順を組み立て、外部システムへ接続する代理演算体である。

では、その代理演算体やサイバーの術は、どうやって現実の場に触れるのか。

この問いに答えるために、スマートデバイスを考える。

本章で行うのは、既存のスマートデバイス設計論を否定することではない。

カメラを載せる。マイクを載せる。センサーを選ぶ。AIを接続する。通信方式を決める。表示方法を設計する。安全範囲を定める。そうした議論は、スマートデバイスを作るうえで当然に必要である。本章の議論は、それらと対立しない。

ここで考えたいのは、同じ設計意図を、日本語の身体感覚に即した言葉で捉え直すと、どう見えるのかである。

その見方では、スマートデバイスは、人の願いから生まれたサイバーの術を現実空間に通し、AIエージェントという代理演算体を現れさせ、働かせるための器として見えてくる。

## 7.1 なぜここまで陰陽師の話をしてきたのか

ここで、前章までの陰陽師や魔法の話が戻ってくる。

それらは、雰囲気を出すための飾りではない。SF風の演出でもない。まして、デジタル技術を本当に陰陽術だと言いたいわけでもない。

陰陽師的に見るとは、状態を読み、符号や作法を扱い、術を通し、代理的なものに働かせ、場を整え、願いを現実の状態変化へつなげる、という操作イメージを持つことである。

この操作イメージは、既存の設計議論を置き換えるものではない。

カメラを載せる。マイクを載せる。AIを載せる。クラウドにつなぐ。スマホアプリで操作する。音声入力に対応する。

こうした言い方は、実務上は正しい。実際に必要な仕様を決めるには、どのセンサーを載せるか、どの通信を使うか、どの処理をどこで行うかを考えなければならない。

ただ、その言葉だけでは、慣れていない読者や設計の入口にいる人には、何を実現しようとしているのかが見えにくいことがある。

感覚に即した言葉で捉え直すと、同じ議論は別の見え方になる。

どんな願いを叶えたいのか。その願いを叶えるには、どんな術が必要なのか。その術を起動する符や作法は何か。その術を実行する代理演算体は、何を見て、何を聞き、どこに現れ、何に触れ、どこで止まるべきなのか。そのために、どんな器が必要なのか。

ここまで陰陽師や魔法の話をしてきたのは、スマートデバイス設計に別の流派を持ち込むためではない。

すでに行われている設計の議論を、日本語話者が直感的に掴みやすい形へ読み直すためである。そう読み直すと、スマートデバイスは「機能の集合」でもありながら、同時に「術を通す器」としても見えてくる。

## 7.2 機能一覧の奥にある願いと術を見る

スマートデバイスは、単体では価値を説明しにくい。

高性能なセンサー。小型の筐体。美しい表示。軽い装着感。精密な加工。長い電池持ち。安定した通信。低遅延の処理。

これらは重要である。むしろ、これらの議論なしにスマートデバイスは作れない。

ただし、それらが何のために必要なのかを説明するとき、部品や性能の言葉だけでは、生活のどの場面をどう変えるのかが伝わりにくいことがある。

それは、魔法のない杖を作るようなものである。

杖がどれほど軽く、美しく、持ちやすくても、その杖で何が起こせるのかが見えなければ、人は欲しいと思わない。

同じように、魔人のいないランプにも意味は少ない。ランプをこすっても何も現れず、願いを聞くものも、手順を組み立てるものも、現実へ働きかけるものもないなら、それはただの容器である。

ここでいう魔法や魔人は、もちろん比喩である。

魔法とは、神秘的な力ではない。人の「こうなってほしい」という願いが、記号、演算、AI、デバイス、表示、空間配置を通じて、現実の状態変化として現れる体験である。

魔人とは、本当に人格を持つ存在ではない。呼び出され、願いを聞き、文脈を読み、手順を組み立て、外部の道具を使い、結果を返す代理演算体である。

杖やランプとは、その魔法や魔人を現実の場に通すための器である。

だから、部品性能の議論と、術の議論は対立しない。

部品性能は、術を通すために必要になる。逆に、どの術を通したいのかが見えると、なぜそのセンサーが必要なのか、なぜその表示が必要なのか、なぜその通信や処理性能が必要なのかが分かりやすくなる。

## 7.3 願いから術を選び、術から器を考える

第3章では、サイバーの技を「どうしたいか」から分類した。

本章では、スマートデバイスの仕様を、この分類から読み直してみる。

まず、願いがある。

部屋を明るくしたい。声を届けたい。状態を見たい。必要な情報をその場に出したい。機械を安全に止めたい。AIエージェントに現実の場で案内してほしい。離れた人と同じ状態を見たい。作業の流れを乱さず、必要なときだけ助けてほしい。

次に、その願いを叶えるための術を考える。

入力が必要なのか。見る技が必要なのか。見せる技が必要なのか。契、つまり起動のきっかけが必要なのか。配線、つまり外部の装置やサービスとの接続が必要なのか。向きや量を与える必要があるのか。相互作用が必要なのか。繰り返し呼び出す必要があるのか。並列に扱う必要があるのか。勢いを整える必要があるのか。

そのうえで、器を考える。

その術を現実空間で働かせるには、どんな目がいるのか。どんな耳がいるのか。どんな声がいるのか。どんな姿で現れる必要があるのか。どこへ手を伸ばす必要があるのか。どの装置とつながる必要があるのか。何を記憶する必要があるのか。どこまで働いてよいのか。

ここから、仕様が出てくる。

この順番を、本章では次のように置く。

```text
願い -> 術 -> 器 -> 仕様
```

実務上は、最終的に仕様書や部品表を書くことになる。

本章でしているのは、その仕様書や部品表の奥にある意図を、願い、術、器という順序で読み直すことである。

何を叶えたいのか。そのためにどんな術が必要なのか。その術を現実に通すには、どんな器が必要なのか。そう考えると、カメラ、マイク、センサー、プロジェクター、スピーカー、通信、演算性能、権限管理、停止条件といった仕様が、単なる項目ではなく、願いを状態変化へつなぐための要素として見えてくる。

## 7.4 AIエージェントは、術を束ねる代理演算体である

AIエージェントは、願いをそのまま現実に変える魔法の存在ではない。

人の言葉は、たいてい曖昧である。

見やすくしてほしい。いい感じに整えてほしい。会議しやすくしてほしい。必要な情報だけ出してほしい。いま何をすればよいか教えてほしい。危なそうなら止めてほしい。

このままでは、装置は動けない。

AIエージェントは、その曖昧な願いを受け取り、文脈を読み、条件を確認し、手順を組み立てる。必要な情報を集め、外部の道具を選び、実行前に確認し、結果を返す。

この意味で、AIエージェントは、第6章で述べた代理演算体である。

それは本当に意思を持つとは限らない。生命でも魂でもない。だが、人の願いを受け、状況を読み、手順を組み立て、外部の道具へ働きを渡すものとして見ると、日本語の感覚では、式神や魔人のように見えることがある。

重要なのは、その見た目ではない。

重要なのは、どの術を束ね、どの器を使い、どの範囲で現実へ作用するのかである。

## 7.5 器としてのスマートデバイス

AIエージェントは、ソフトウェアだけでは現実に触れられない。

部屋の明るさを変えるには、照明に触れる必要がある。音を返すには、スピーカーがいる。人の声を聞くには、マイクがいる。周囲を見るには、カメラがいる。状態を読むには、センサーやログがいる。空間に情報を出すには、ディスプレイやプロジェクターがいる。物理的な動きを作るには、モーターやロボットやアクチュエータがいる。

スマートデバイスは、AIエージェントが現実へ触れるための器である。

この器は、単なる外装というより、代理演算体がどのように現れ、どのように聞き、どのように見て、どこへ作用し、どこで止まるかを、利用者に分かる形へ翻訳する場である。

器の役割は、次のように整理できる。

| 器の役割 | 技術的な対応 |
|---|---|
| 目 | カメラ、センサー、ログ、状態取得 |
| 耳 | マイク、音声認識、イベント入力 |
| 声 | スピーカー、音声応答、通知 |
| 姿 | ディスプレイ、プロジェクション、アバター、状態表示 |
| 手足 | アクチュエータ、家電制御、ロボット、API |
| 通路 | 通信、プロトコル、デバイス連携、外部サービス接続 |
| 記憶 | ログ、履歴、設定、ユーザー文脈、RAG |
| 結界 | 権限、安全範囲、停止条件、プライバシー、失敗時の動作 |
| 換装性 | 更新、拡張、ライブラリ差し替え、外部エージェント接続 |

この表は、比喩遊びではない。

すでに仕様として議論されている要素を、術と代理演算体の側から読み直すための対応表である。

どんな目が必要かを考えると、センサーの意味が分かりやすくなる。どんな姿で現れるべきかを考えると、表示方式やプロジェクションの要件が分かりやすくなる。どこへ手を伸ばすべきかを考えると、APIやアクチュエータの要件が分かりやすくなる。どこまで働いてよいかを考えると、権限や停止条件の意味が分かりやすくなる。

## 7.6 結界としての安全範囲

器を考えるとき、結界という補助線は重要である。

ここでいう結界は、神秘的な結界ではない。権限、安全範囲、停止条件、プライバシー、失敗時の動作を定めることである。

AIエージェントが現実に触れるなら、どこまで見てよいのか、何を聞いてよいのか、どの装置を動かしてよいのか、どの条件では確認を挟むのか、どの条件では自動で止まるのかを決めなければならない。

スマートデバイスは、AIを自由に現実へ放つための器ではない。

むしろ、AIエージェントが現実に触れる範囲を、人間が理解でき、許可でき、止められる形にするための器である。

この意味で、良い器には、目や手足だけでなく、結界が必要である。

## 7.7 同じ設計を、別の言葉で見直す

スマートデバイスの設計では、部品や機能から考える場面がある。

AIを載せる。センサーを増やす。スマホアプリを作る。音声操作にする。クラウドにつなぐ。小型化する。電池を長持ちさせる。

これは間違いではない。むしろ、実際の開発では避けられない。

本章で試みているのは、その同じ設計を、別の言葉で見直すことである。

この人は、どんな願いを持っているのか。その願いを叶えるには、どんな術が必要なのか。その術を実行する代理演算体は、何を見て、何を聞き、どこに現れ、何に触れ、何を記憶し、どこで止まるべきなのか。そのために、器は何を備えるべきなのか。

これは、部品から考える議論を否定するものではない。

むしろ、同じ議論を、使う人の願い、AIエージェントの働き、現実の状態変化に結びつけ直すための言い換えである。

何の魔法を通すのかが見えると、杖の重さや形や材質の意味が分かりやすくなる。何の魔人を呼ぶのかが見えると、ランプの形や呼び出し方や安全範囲の意味が分かりやすくなる。

スマートデバイスも同じである。どんな術を通す器として見るのかが分かると、センサー、表示、通信、筐体、電池、処理性能、安全機構の意味が、生活感覚の中でつながって見えてくる。

## 7.8 `sword-voice-agent` をどう位置づけるか

`sword-voice-agent` は、この章の考え方を小さく実装した例として扱える。

刀印で入力ゲートを開く。音声で願いを伝える。AIエージェントが文脈を読み、手順を組み立てる。アバター、音声、投影表示、家電操作、外部サービス接続へつなぐ。

この例で重要なのは、刀印が和風だから面白いという点ではない。

刀印は、偶発動作と混同されにくい身体入力であり、AIへ一時的に権限を渡す作法である。音声は願いを渡す経路である。AIエージェントは代理演算体である。プロジェクションは、AIの状態や結果を場に見せる姿である。家電操作や外部サービス接続は、現実へ触れる手足である。

つまり、この実装は、願い、契、代理演算体、器、結界を一つの小さな流れとして示している。

ただし、この例を章の中心にしすぎない。

`sword-voice-agent` は、本章の考え方を体験的に示す具体例であって、主題ではない。主題は、スマートデバイスを術と代理演算体を現実に通す器として考えることである。

## 7.9 第8章への接続

ここまで、AIエージェントがスマートデバイスを器として使い、現実に触れる構造を見た。

AIエージェントは、マイクで聞き、カメラで見て、センサーで状態を読み、スピーカーで返し、プロジェクターで姿を出し、家電やロボットやAPIを通じて現実へ作用する。

では、この構造はAIだけのものなのか。

そうではない。

人間もまた、AI、記録、プロンプト、表示装置、スマートデバイスを外部器官として使う。記憶を外に置き、判断を補助し、言語化を助け、状態を見せ、行為を支え、生き残る経路を増やす。

AIがスマートデバイスを身体として使うなら、人間もまた、AIやデバイスを身体の外へ広がる器官として使っている。

次章では、この反転を見る。

スマートデバイスは、AIの身体であるだけではない。人間にとっても、記憶、判断、表示、行為を外へ広げる外部器官になりうる。

## 7.10 仮結論

スマートデバイスの価値は、ハードウェア単体では決まらない。

重要なのは、その器に、どのような術を通せるかである。

人の願いを読み、必要な術を選び、代理演算体を働かせ、現実の状態変化として返す。そのために、どんな目、耳、声、姿、手足、通路、記憶、結界、換装性を備えるべきか。

そこから、センサー、表示、通信、演算性能、更新性、安全性といった要求仕様が決まる。

スマートデバイスを作る議論は、最終的には部品、仕様、性能、価格、量産性、安全性の議論になる。

本章で述べたかったのは、その議論の前に別の正解を置くことではない。

同じ議論を、願いから術を見つけ、その術を現実に通す器を設計する話として読み直すと、何を作ろうとしているのかが分かりやすくなる、ということである。

この意味で、前章までの陰陽師的な話は、ここで初めて設計論へ回収される。

状態を読み、符号や作法を扱い、代理的なものに働かせ、場を整え、現実の状態変化へつなげる。その見方を持つと、スマートデバイスは「便利な電子機器」であると同時に、「術を通す器」としても見えてくる。

魔法の内容が見えると、杖の仕様が分かりやすくなる。

魔人が何をする存在なのかが見えると、ランプに必要な器としての条件が分かりやすくなる。

スマートデバイスとは、願いから生まれた術と、それを実行する代理演算体を、現実の場に通すための器なのである。

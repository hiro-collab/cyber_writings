## 統合する核

今回の追加素材は、単なる語源メモではない。

中心は、プログラミング学習の前提として「自分のサイバー空間を持ち、それを統治する」という基本観念を入れることにある。

この前提を置くと、次の論点がつながる。

- 一般的な感覚では、ユーザーがコンピューターへ渡すものは「お願い」に近い。
- しかし `command` があえて「命令」と訳されるのは、対象が統治されたサイバー領域の中にあり、権限ある主体の実行指示を受けて動くよう設計されているからである。
- この統治の観念を抜いたまま「命令」とだけ教えると、日本語話者には軍隊的・上意下達的な語に見え、プログラミングの実感から離れやすい。
- プログラミング学習者は、ゲストユーザーから管理者ユーザー側へ移っていく人として説明できる。

## 第2部へ入れる内容

### サイバー空間を持つとは、統治する領域を持つことである

第2部の `操るとは何か` と `望みとお願い` の間に新節として入れる。

採用する整理:

- サイバー空間は、単なるインターネット上の場所ではない。
- 自分が触れ、変え、実行し、守る責任範囲である。
- ファイル、アプリ、プロセス、権限、通信、アカウント、外部サービスとの接続を含む。
- 操るには、まずその領域を操れる状態に保つ必要がある。
- これを本書では、政治的支配ではなく、状態把握、権限設定、実行範囲、停止条件、復旧、保守を含む「統治」として扱う。

定義候補:

> サイバー空間を持つとは、操れる対象を持つだけでなく、その対象が操れる状態を維持する責任範囲を持つことである。

### ゲストユーザーと管理者ユーザー

学習用の概念として導入する。

- ゲストユーザー: 用意された範囲で使う人。ボタンを押す、選択肢を選ぶ、入力欄に書く。領域のルールそのものは変えない。
- 管理者ユーザー: 領域のルールを整える人。何を置くか、何を動かすか、誰に触らせるか、どこまで実行してよいか、失敗時にどう止めるかを決める。
- プログラミング学習者: ゲストとして使う側から、少しずつ管理者側へ移る人。

この整理により、`command` は「ただのお願い」ではなく、管理された領域内での形式化された実行指示として説明できる。

## 第1部へ入れる内容

`command = 命令` は間違いではない。ただし、その前提を教えないと違和感が出る。

採用する整理:

- ユーザーの感覚では、コンピューターへ渡すものは「こうしてほしい」というお願いに近い。
- しかし、システム側から見ると、正当な権限、正しい形式、実行条件がそろえば実行されるよう設計された指示である。
- だから `command` は「命令」と訳される。
- 問題は、「命令」という訳そのものではなく、その背景にあるサイバー領域、権限、実行条件、責任を説明しないことにある。

## 第4部へ入れる内容

`code / codex / 符 / 符号 / 符文` は、第4部 4.5 を短く補強する。

採用する整理:

- `code` と `符` は同語源ではない。
- `code` は `codex` 系の語で、木板・書物・法典・規則体系・信号体系・コンピューター用の情報表現へ展開した。
- `符` は割符・証拠札・しるし・記号の語である。
- `号` は叫ぶ、呼ぶ、名づける、合図する方向の字である。
- `符号` は短い記号、信号、識別子、体系化された記号列には合う。
- 長い `source code` は、短い合図ではなく、構文を持つ記述であるため、試験的に `符文` と呼ぶ理由が立つ。

## 本文に入れない内容

- `code` と `符` は同じ語源である、という言い方。
- 「命令」は語源的に命を懸ける令である、という断定。
- 欧米では説明不要、日本では説明必要、を民族性の違いとして断定する言い方。
- 「統治」を政治的支配や人格支配として広げすぎること。

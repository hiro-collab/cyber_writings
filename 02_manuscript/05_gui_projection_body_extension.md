# 第5部　GUI、プロジェクション、身体拡張

## 第5章　願いを見える形にする

この第5部から第7部までは、現時点では応用編として仮置きしている。第1部から第4部で置いた「訳し直し」「操る」「技の分類」「語感のリスク」を、GUI、プロジェクション、AI、スマートデバイスの具体例へ接続できるかを試す部分である。

### 5.1 GUI は願いを選ぶ装置である

GUI は、コマンドラインより分かりやすいと言われることがある。

その理由は、GUI が人の意図を、あらかじめ見える選択肢として配置するからである。

ボタン、メニュー、アイコン、スライダー、チェックボックス、タブ。これらは単なる飾りではない。人が「こうしたい」と思う可能性のある操作を、画面上に並べたものである。

- これを表示したい
- これを起動したい
- これを止めたい
- この値を変えたい
- この状態へ切り替えたい
- この結果を確認したい

GUI は、こうした願いを選べる形にする。

ただし、GUI だから常に操りやすいわけではない。ボタンが多すぎれば迷う。見た目が整っていても、願いと結果の対応が分からなければ使いにくい。

重要なのは、GUI という形式そのものではない。

重要なのは、願いから結果までの距離を短くすることである。

過去の実装記録では、製品デモ用の GUI を「これを選ぶ」＋「表示する」の二操作で完結させようとしたことがある。これは単なる省力化ではない。現場で使う人が、コマンドや内部構造を思い出さなくても、見せたいものを選び、すぐ表示できるようにするためである。

### 5.2 コマンドと GUI の違い

コマンドラインでは、人が願いを記号化して入力する。

コマンド名、オプション、引数、パス、権限。これらを知っていれば、非常に強力に操れる。しかし、知らなければ何もできない。

GUI では、その一部が見える選択肢として配置される。また、「押すか押さないか」という選択肢を絞る効果もある。

たとえば「保存」というボタンがある。ユーザーは内部のファイル書き込み処理を知らなくても、保存したいという願いを選べる。

つまり GUI は、コマンドを消したのではない。願いとコマンドの間に、見える選択肢を置いたのである。

この観点から見ると、GUI 設計とは、願いの配置である。

何を見えるようにするか。何を隠すか。どの願いをボタンにするか。どの願いをメニューに下げるか。どの操作は確認を挟むか。

GUI は、単なる見た目ではなく、操るための構造である。

### 5.3 プロジェクターは「見る」装置だけではない

プロジェクターは、一般には映像を見るための装置として扱われる。

しかし、本書ではプロジェクターを「見せる」装置として重視する。

ディスプレイは、個人が画面を見る装置として優れている。スマートフォンや HMD は、個人の視界へ情報を出す装置として強い。

一方、プロジェクターは空間に映像を出す。

壁、床、机、扉、家具、舞台、都市空間。そこに情報を重ねることで、操作結果やシステムの状態を、その場にいる人へ見せられる。

大きなディスプレイを持ち歩くのは難しい。しかしプロジェクターなら、周囲の空間を一時的な表示面として使える。

これは、単に大画面を作るという話ではない。

情報を空間に現すことで、操作と結果を共有できるようにする話である。

この点は、私自身の映像パフォーマンスの経験とも重なる。路上で映像をただ映すだけでは、意外なほど人は動かない。映像がその場の音、人の動き、空間の状態に応じて変わり、操られていることが見えたとき、初めてそこに驚きや感動が生まれる。あとから考えれば、それは「映像を見る」ことではなく、「映像で空間を操る」ことだった。

### 5.4 「見る」と「見せる」を分ける

サイバーの技の分類では、「見る」と「見せる」を分けた。

見るとは、状態を把握可能にすることである。デバッグ用のログ、センサー値や内部状態、処理の途中経過の参照可能化などがここに入る。

見せるとは、状態や結果を、誰かにどう受け取られるかまで含めて整えることである。

同じデータでも、デバッグ用に見るのと、観客に見せるのでは違う。AI エージェントの内部状態を開発者が確認するのと、ユーザーに「処理中です」と示すのでは違う。

プロジェクターは、この「見せる」技と相性がよい。

人が画面の前に座っていなくても、空間の中で情報を示せる。音声だけでは伝わりにくい状態を、光、色、位置、動きとして出せる。

### 5.5 投影型 AR を重視する理由

HMD は強力である。個人の視界に情報を重ねられる。

しかし、HMD は装着した人にしか見えない。人に見せるには、相手にも装着してもらう必要がある。

投影型 AR は、その場の空間そのものへ情報を出す。

- 複数人が同じ情報を見る
- 操作結果がその場に現れる
- 音声ではなく光で状態を示す
- 必要な場所にだけ情報を置く
- 現実の物体と情報を重ねる

この特性は、AI、センサー、家電、ロボット、人間の対話に向いている。

たとえば AI が「このスイッチを押してください」と言うだけでなく、実際の壁のスイッチ付近に光を投影する。床に経路を示す。机の上に確認事項を出す。家具の上に状態を重ねる。

これは、情報を見るための表示ではなく、現実を操るための表示である。

### 5.6 刀印と身体化された入力

`sword-voice-agent` のような実験では、刀印に似た手指ポーズを、AI エージェントへの入力ゲートとして使う。

ここで重要なのは、刀印が和風だから面白い、という話ではない。

ジェスチャー UI では、起動ジェスチャーが日常動作と混同されにくいことが重要である。また、形そのものが覚えやすく、意味と対応していることも重要である。

刀印は、日常生活の中で偶然出にくい。人差し指と中指を伸ばすだけなので身体的負担も大きくない。「刀」の形として意味づけしやすく、AI を呼び出す、あるいは入力権限を開く作法として覚えやすい。

つまり、刀印は単なる演出ではなく、誤作動しにくさ、記憶しやすさ、身体負荷、権限の明示を兼ねた入力である。

[要確認] Ultraleap / Leap Motion のジェスチャー設計原則。偶発動作との混同回避、記憶容易性、意味対応に関する一次資料。

### 5.7 入力の身体化、出力の空間化

刀印は、入力を身体化する。

プロジェクターは、出力を空間化する。

この二つを組み合わせると、AI エージェントとの関係が、画面の中だけで完結しなくなる。

人が身体で入力ゲートを開く。声で願いを伝える。AI が解釈する。家電やサービスを動かす。状態や結果が壁や床や物体の上に出る。

ここでは、サイバーの技が一つに束ねられている。

入力、トリガー、配線、出力、見る、見せる、相互作用、勢い。これらが生活空間の中でつながる。

この意味で、GUI、ジェスチャー、プロジェクションは、別々の話ではない。

どれも、願いを現実の操作へつなげるための接点である。
